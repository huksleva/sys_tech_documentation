# DEV: Alien Invasion

Разработка, проверки и согласование источников. Сборка из атомарных карточек от 21.10.2026.

Документ сохраняет статусы карточек. Проектные требования, выводы и предложения не являются утверждением о готовой реализации. Источники и подробные связи доступны по ссылкам.

## Проверка правила начинается с наблюдаемого результата

[Карточка 20261021000021](../vault/20261021000021.md).

Для каждого изменяемого правила нужно задать исходное состояние, одно действие и наблюдаемый результат. Например: три пули до Space и три пули после Space подтверждают отказ при заполненном залпе.

В ЛР6 уже есть проверки лимита пуль, границ, повторного запуска и перехода уровня. Здесь эти тесты изучены как источник, но повторный прогон игры и её тестов не выполнялся.

- [20261021000009](../vault/20261021000009.md) SRS - Четвёртая активная пуля не создаётся. Даёт пример дискретного ограничения.
- [20261021000011](../vault/20261021000011.md) SRS - Повторный Play сбрасывает только данные партии. Даёт сценарий со сбросом нескольких полей.
- [20261021000017](../vault/20261021000017.md) SDD - Дробная координата сохраняет малое перемещение. Даёт граничный случай дробной скорости.
- [20261021000030](../vault/20261021000030.md) SUP - Патч должен сохранять проверяемые правила. Определяет минимальную регрессионную проверку патча.

## Расхождение кода и проекта требует явного решения

[Карточка 20261021000022](../vault/20261021000022.md).

ЛР5 описывает три жизни всего, а ЛР6 хранит три замены сверх текущего корабля: завершение происходит после четвёртого попадания. Это различие терминов и поведения, которое нельзя скрыть общим словом «жизни».

Для текущих карточек фактом реализации считается код ЛР6; правила ЛР5 помечены как проект. Перед изменением нужно выбрать контракт и согласовать GDD, SRS, SDD и связанные проверки.

- [20261021000008](../vault/20261021000008.md) GDD - HUD показывает состояние без выхода из партии. Показывает пользователю неоднозначный запас.
- [20261021000018](../vault/20261021000018.md) SDD - Групповая коллизия начисляет очки за все цели. Даёт ещё один пример расхождения контракта.
- [20261021000021](../vault/20261021000021.md) DEV - Проверка правила начинается с наблюдаемого результата. Требует согласовать ожидаемый результат теста.
- [20261021000033](../vault/20261021000033.md) IDEA - Таймер восстановления сохранит обработку событий. Превращает расхождение восстановления в отдельное предложение.

## Поставка должна фиксировать зависимости и ресурсы

[Карточка 20261021000023](../vault/20261021000023.md).

Исходный дистрибутив игры должен содержать сведения о зависимостях и оба изображения. В pyproject.toml ЛР6 указаны Python >=3.11 и Pygame >=2.6.1,<3.0, а BMP включены как данные пакета.

Установка и запуск из другой рабочей папки выявляют потерянные ресурсы лучше, чем запуск из исходного каталога разработчика.

- [20261021000019](../vault/20261021000019.md) SDD - Ресурсы ищутся относительно пакета. Объясняет независимый от текущей папки поиск ресурсов.
- [20261021000012](../vault/20261021000012.md) SRS - Базовая игра работает без сети. Отделяет установку от офлайн-партии.
- [20261021000026](../vault/20261021000026.md) MKT - Открытая учебная поставка поддерживает разбор механик. Определяет содержимое учебной поставки.
- [20261021000030](../vault/20261021000030.md) SUP - Патч должен сохранять проверяемые правила. Требует повторной проверки после упаковки патча.

## Небольшой вертикальный срез проверяет идею быстрее

[Карточка 20261021000024](../vault/20261021000024.md).

Улучшение стоит выпускать одним проверяемым срезом: правило, представление, реализация, проверка и отзыв. Например, индикатор залпа можно оценить без добавления нового оружия или уровня.

Предлагаемая очередь: сначала индикатор слотов, затем предупреждение об угрозе; восстановление и изменение единиц скорости требуют отдельной технической проверки.

- [20261021000015](../vault/20261021000015.md) SDD - Контроллер координирует объекты одного кадра. Помогает определить затронутые компоненты.
- [20261021000021](../vault/20261021000021.md) DEV - Проверка правила начинается с наблюдаемого результата. Задаёт проверку нового правила.
- [20261021000027](../vault/20261021000027.md) MKT - Отзыв полезнее привязывать к наблюдаемому затруднению. Возвращает наблюдения игрока в следующий срез.
- [20261021000031](../vault/20261021000031.md) IDEA - Индикатор залпа объяснит недоступный выстрел. Даёт первый ограниченный по объёму эксперимент.
