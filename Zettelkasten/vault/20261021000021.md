# DEV - Проверка правила начинается с наблюдаемого результата

Теги: #DEV #testing #requirements

## Идея

Для каждого изменяемого правила нужно задать исходное состояние, одно действие и наблюдаемый результат. Например: три пули до Space и три пули после Space подтверждают отказ при заполненном залпе.

## Обоснование и проверка

В ЛР6 уже есть проверки лимита пуль, границ, повторного запуска и перехода уровня. Здесь эти тесты изучены как источник, но повторный прогон игры и её тестов не выполнялся.

## Связи

- [[20261021000009]] SRS - Четвёртая активная пуля не создаётся. Даёт пример дискретного ограничения.
- [[20261021000011]] SRS - Повторный Play сбрасывает только данные партии. Даёт сценарий со сбросом нескольких полей.
- [[20261021000017]] SDD - Дробная координата сохраняет малое перемещение. Даёт граничный случай дробной скорости.
- [[20261021000030]] SUP - Патч должен сохранять проверяемые правила. Определяет минимальную регрессионную проверку патча.
