## 1. Цель и исходные материалы

Цель: реализовать выданную игру, описать контракты всех Python-исходников
русскоязычными Google-style docstrings, сгенерировать API-сайт и настроить
проверяемую поставку. Использованы `alien-invasion-starter.zip` и русская
методичка `Alien-Invasion-Codebase-Documentation-Lab.pdf`. Файл `.zh-CN.pdf`
содержит перевод и не меняет язык результата. Папка названа `ЛР6` согласно
номеру работы в запросе; приведённая в описании тема обозначена как лабораторная №5.

Сохранены структура заготовки, имена классов/методов, BMP и исходные шесть
acceptance-сценариев. На неизменённой заготовке результат: **5 failed, 1 passed**.
Это ожидаемые ошибки незавершённой механики; импорт и окружение работали.

## 2. Реализация игры

Реализованы Play и повторный запуск, удержание стрелок, выстрел Space, выход Q,
лимит трёх пуль, движение и удаление пуль, флот с разворотом у края, коллизии,
очки, рекорд процесса, переход уровня, рост сложности, потеря корабля и HUD.

У исходного теста особая семантика `ships_left`: это запас замен. При значении 1
попадание оставляет активную игру с нулём замен; следующее попадание завершает
сессию. При начальном запасе 3 Game Over наступает после четвёртого попадания.
Контракт сохранён и описан в [игровом цикле](docs/game-loop.md).

Корабль ограничивается границами даже при дробном шаге. Ресурсы загружаются
через `importlib.resources`; запуск не зависит от рабочей папки. Новая сессия
сбрасывает настройки и статистику, сохраняя рекорд. Частота ограничена 60 FPS;
скорости заданы в пикселях за кадр. После потери корабля предусмотрена пауза 0,5 с.

## 3. Документация кодовой базы

Документированы **19 Python-файлов и 109 единиц**: модули, классы, все
именованные функции и методы, включая `_`-методы, launcher, архиватор и тесты.
Описания русские; секции `Args`, `Attributes`, `Returns`, `Raises` и `Yields`
используются по смыслу. BMP, кэши, окружения и сгенерированные артефакты не
входят в инвентаризацию исходников.

Подготовлены 10 страниц Markdown:

- [Обзор проекта](docs/README.md), [архитектура](docs/architecture.md) и [игровой цикл](docs/game-loop.md).
- [Справочник кода](docs/code-reference.md), [тестирование и поставка](docs/testing-and-delivery.md), [руководство студента](docs/student-guide.md).
- [Карта API](docs/api/index.md), [игровой пакет](docs/api/runtime.md), [инструменты и тесты](docs/api/tooling-and-tests.md), [матрица покрытия](docs/api/codebase-coverage.md).

API собирается mkdocstrings непосредственно из docstrings. Корневой launcher
включается листингом, потому что его имя совпадает с именем игрового пакета.
Material for MkDocs даёт русскую навигацию и поиск, готовые CSS/JavaScript;
загрузка внешних шрифтов отключена. Сайт находится в `site/index.html`.

## 4. Инструменты качества и сборки

В [pyproject.toml](pyproject.toml) выделены основная зависимость Pygame,
группа `dev` с pytest, Ruff и Poe, optional-группа `docs` с MkDocs Material
и mkdocstrings. [poetry.lock](poetry.lock) фиксирует разрешённые версии.

| Задача Poe | Действие |
|---|---|
| run | Запуск игры |
| format | Изменяющее автоформатирование Ruff |
| format-check | Проверка форматирования без исправлений |
| docs-check | Линтинг, импорты и Google-style docstrings |
| compile | Проверка синтаксиса Python через compileall |
| test | Headless-тесты pytest |
| docs-site | Строгая сборка сайта MkDocs |
| docs-serve | Предварительный просмотр с пересборкой |
| archive | Воспроизводимый ZIP с кодом и сайтом |
| check | format-check → docs-check → compile → test |
| build | format → check → docs-site → archive → poetry build |

Ruff проверяет ошибки Python, импорты и Google-style; редкие `E402` исключены
только для launcher (путь `src` должен настраиваться до импорта) и conftest
(SDL должен настраиваться до Pygame). Тесты используют importlib-режим pytest,
чтобы корневой launcher не подменял одноимённый пакет.

## 5. Проверка результата

Проверено на Windows, Python 3.13.2, Pygame 2.6.1, Poetry 2.5.1,
Ruff 0.16.10, pytest 8.4.2, MkDocs 1.6.1 и Material 9.7.7.

**29 тестов проходят:** 6 исходных acceptance-тестов, 14 дополнительных
игровых сценариев и 9 проверок документации/поставки. Дополнительные сценарии
проверяют ввод, повторный запуск, дробные границы, освобождение слота пули,
несколько целей одного выстрела, нижнюю границу, однократную потерю запаса,
Game Over, выход и загрузку package data.

Метапроверки охватывают docstrings у всех определений, непустые страницы,
относительные ссылки рекурсивно внутри `docs`, соответствие nav и матрицы
исходникам, директивы всех модулей, последовательности Poe, белый список ZIP
и побайтную воспроизводимость. Строгая сборка дополнительно проверяет API.

Все задачи `format`, `check`, `docs-site`, `archive` и `build` завершились с
кодом 0. `poetry check --lock` также успешен. Сайт просмотрен в браузере:
русский поиск по «запас корабля» вернул 4 страницы, API показывает внутренние
методы. Стартовый и активный экран Pygame проверены по отрисованным поверхностям.
Проверены все 11 HTML-страниц: отсутствуют битые локальные файлы и якоря.
Wheel установлен в отдельное чистое окружение только с Pygame: успешно
проверены ресурсы, активный кадр, выход и точка входа `python -m alien_invasion`.
Проверен состав wheel и sdist: BMP присутствуют в обоих, документация и сайт
есть в sdist и исключены из wheel, кэши отсутствуют.

## 6. Запуск и воспроизведение

Команды выполняются из `ЛР6`; нужны Python 3.11+ и Poetry:

```powershell
poetry install --with docs
poetry run poe run
poetry run poe format
poetry run poe check
poetry run poe docs-site
poetry run poe archive
poetry run poe build
```

Для просмотра готового сайта:

```powershell
python -m http.server --directory site 8000
```

Адрес: `http://localhost:8000`. Для редактирования: `poetry run poe docs-serve`.
Управление: Play, стрелки влево/вправо, Space, Q или закрытие окна.
После установки только основных зависимостей (`poetry install --only main`)
игра запускается `poetry run alien-invasion` без MkDocs и инструментов проверки.

В текущем рабочем каталоге Poetry установлен локально для проверки лабораторной.
Если команда `poetry` недоступна в PATH, можно использовать:

```powershell
.\.tools\Scripts\poetry.exe run poe check
.\.tools\Scripts\poetry.exe run poe run
```

## 7. Поставка

[Архиватор](scripts/package_tools.py) включает только обязательные корневые
файлы и `docs`, `scripts`, `site`, `src`, `tests`. ZIP не содержит `.venv`,
локальные инструменты, кэши, байткод, Git и сам `dist`. Порядок, timestamps
и права фиксированы; повторная упаковка одного снимка даёт одинаковые байты.

Результаты находятся в `dist/`:

- `alien-invasion-0.1.0-source.zip`: код, Markdown, конфигурации, lock и готовый сайт.
- `alien_invasion-0.1.0-py3-none-any.whl`: устанавливаемый игровой пакет с BMP.
- `alien_invasion-0.1.0.tar.gz`: исходный дистрибутив, включая документацию и сайт.

Документация включена в sdist, но не в wheel. Окружения, локальные кэши и
служебные файлы исключены из Git; сайт и три артефакта поставки сохраняются.
